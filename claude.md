# Meridian — agent notes

Chrome MV3 extension: transparent Twitch chat overlay on YouTube.

## Auth strategy
Anonymous read-only by default; the user explicitly links their account via Twitch's official OAuth. **We do NOT read twitch.tv cookies** (that violates Twitch's Developer Services Agreement).

1. **Anonymous (default).** `NICK justinfan<random>`, no PASS. Send input is disabled.
2. **OAuth (opt-in "Connect Twitch").** `chrome.identity.launchWebAuthFlow` implicit grant (`response_type=token`, scopes `chat:read chat:edit`, redirect `https://<ext-id>.chromiumapp.org/`). Needs a registered Client ID in `src/config.js` (`TWITCH_CLIENT_ID`); the popup's General tab shows the redirect URL to register and the connect/disconnect buttons. Token validated at `id.twitch.tv/oauth2/validate`, stored in `meridian.oauth`, used as `oauth:<token>` for IRC. `resolveAuth()` returns the stored token if it still validates, else anonymous.

`background.js` exposes: `AUTH_GET`, `AUTH_CONNECT` (interactive), `AUTH_DISCONNECT`, `AUTH_STATUS`. `src/config.js` holds `TWITCH_CLIENT_ID` + `TWITCH_SCOPES`. Content script reconnects when `meridian.oauth` changes.

## Layout
- `manifest.json` — MV3. Perms: `storage`, `identity`, `activeTab` (popup reads the active tab's host). Hosts: youtube.com, kick.com, *.twitch.tv, id/api.twitch.tv, 7tv.io, betterttv, frankerfacez. Content script runs on youtube.com + kick.com only (minimal permissions — no arbitrary-site support).
- `src/background.js` — OAuth connect/disconnect + token validation + display-name enrichment via Helix `/users`.
- `src/config.js` — `TWITCH_CLIENT_ID` (blank until the user registers an app) + `TWITCH_SCOPES`.
- `src/content.js` — overlay DOM, drag/resize, hide/show, delay queue, emote rendering + autocomplete, idle timer.
- `src/twitch-irc.js` — IRC-over-WSS. Supports `anonymous: true` (no PASS). Captures `display-name` from `GLOBALUSERSTATE`/`USERSTATE` tags. Self-echoes sent messages. Unwraps CTCP `/me` (`ACTION …`) messages into clean `text` + an `action` flag — otherwise the trailing control char sticks to the last token and breaks emote matching (e.g. bot `/me` lines ending in `FeelsGoodMan`); emote-tag offsets are parsed against the unwrapped text.
- `src/mappings.js` — **single source** of the seeded default channel mappings (`DEFAULT_MAPPINGS` / `DEFAULT_KICK_MAPPINGS`). ES module imported by both content.js (dynamic `import(getURL(...))`, so it's in `web_accessible_resources`) and popup.js (static `import`).
- `src/emotes.js` — 7TV/BTTV/FFZ registry with on-demand load + cache.
- `src/highlights.js` — `HighlightEngine`: emote-surge detection (unique viewers per emote per window).
- `src/overlay.css` — overlay styling.
- `src/popup.{html,js,css}` — Twitch connect/disconnect, mappings, chat/appearance/hotkey settings.
- `setup.sh` — launches Chrome/Brave/Edge with `--load-extension`.

## Storage keys
- `meridian.oauth` — `{ kind:"oauth", accessToken, login, displayName, userId, scopes, clientId, expiresAt }` (set by Connect, removed by Disconnect)
- `meridian.prefs` — `{ mappings, overrideChannel, rect, hidden, extensionEnabled, chatDelaySec, updateFrequencyMs, autoscroll, hotkeyToggle, hotkeyFocus, opacity, fontSize, maxMessages, blurEnabled, bgEnabled }` — `rect` is computed from viewport on first run (middle-right, ~24% × 42%, clamped 260–340 × 220–340 px). The floating toggle bubble is always shown while the overlay is hidden (no opt-out). Mappings are seeded with default esports YouTube/Kick → Twitch entries from `src/mappings.js` (`DEFAULT_MAPPINGS` / `DEFAULT_KICK_MAPPINGS`, the single shared source).
- `meridian.emotes.v3.__global`, `meridian.emotes.v3.<channel>` — cached emote maps (24 h TTL; not cached if empty or if the 7TV fetch failed, so a transient 7TV blip can't bake a 7TV-less set into the cache)
- `meridian.prefs.extensionEnabled` — master on/off switch (default true). When false the content script early-returns at the enable gate (everything torn down); flipping it reloads the page.
- `meridian.prefs.sites` — `{ "<host>": { mode: "auto"|"overlay"|"docked", hidden: bool } }` per-origin display mode + transient hidden flag (default mode **auto** = overlay in fullscreen, docked otherwise; falls back to overlay when no dock anchor exists, e.g. VODs). `hidden` is toggled by the × / chat bubble / hotkey, kept separate from `mode` so the popup dropdown always shows the state chat returns to. (Legacy `enabled:false` still honored by `siteEnabled()` for back-compat but no longer set by the UI.)
- `meridian.prefs.highlight*` — `highlightTimeline` (master: msgs/sec density wave, default on), `highlightEnabled` (emote surge markers, default on — **independent of the wave**: can be enabled with `highlightTimeline` off, in which case the wave layer still mounts to host the markers but no wave path is drawn and density isn't recorded; `waveActive()` is true when *either* pref is on), `highlightThreshold` (global default unique viewers, floor 3, default 5) + `highlightThresholds` (`{ "<twitch-channel>": threshold }` per-channel overrides — `highlightThreshold()` in content.js returns the active channel's override else the global; read live by `HighlightEngine.getThreshold` so it applies to new surges immediately; popup "Save" writes per-channel when a channel is active, "Set global" always writes the default) + `highlightWindowSec` (global default rolling unique-viewer window, 2..120, default 12) + `highlightWindows` (`{ "<channel>": seconds }` per-channel overrides — `highlightWindow()` resolves per-channel-else-global, fed live to the engine via `getWindowMs`; popup "Save"/"Set global" mirror the threshold), `highlightAnchorLive`, `highlightOffsetSec` (shift wave+markers N s into the past for reaction time, default 5), `highlightColor` (wave gradient + topline + marker accent, default light purple `#b388ff`). Both the wave and the emote markers are keyed to the **seekbar stream-time** (aria-valuemax coordinate), so they scroll/scale in exact lockstep and timestamps are fixed wrt stream start.
- `meridian.prefs` (appearance) also has `textStyle` (`none`|`shadow`|`outline`) + `boldText` (message body weight; names always one step heavier) + `outlineEnabled` (1px border around the panel, `.no-outline`)
- `meridian.highlights.<host>.<videoId|channel>` — persisted emote highlights (array, capped 300), gated on `prefs.highlightPersistEmotes`
- `meridian.density.<host>.<videoId|channel>` — persisted intensity-timeline wave (`DensityTracker.serialize()`: `{baseRes, buckets:[[i,w]…]}`, ~22k-bucket cap), gated on `prefs.highlightPersistDensity`. **VOD replay:** a YouTube livestream keeps the same `watch?v=<id>` URL after it ends, so both keys re-load by that videoId and replay the wave + markers on the archive (`replayLoaded` flag → `waveActive()` true when not live but persisted data exists; the live→ended transition reuses in-memory data). Recording is **live-only** (`recordingActive()` gates the per-message hot path) — on a VOD the IRC carries the channel's *current* chat, which must never be written into the archived timeline.
- `meridian.prefs._activeChannel` — transient side-channel: the content script writes the currently-joined Twitch channel here (on join in `syncChannel`, cleared in `disconnectIRC`) so the popup can scope the per-channel threshold UI to the live channel. Global key, last-writer-wins across tabs.
- `meridian.ui` — `{ tab }` (last popup tab)

## Sites (multi-site adapters)
`content.js` picks a `SITE` adapter by `location.hostname`: `kickAdapter` on kick.com, else `youtubeAdapter`. youtube = player `#movie_player`, handle from the watch-page `/@handle` owner link, nav via `yt-navigate-finish`. kick = player is the `<video>`'s nearest sized container, handle = `kick.com/<slug>`, nav via the 2 s poll. Each adapter exposes `findPlayer()`, `detectHandle()`, `navEvent`. **Kick selectors are unverified against live DOM — confirm before trusting bound mode there** (if `findPlayer()` returns null, bound mode falls back to fixed positioning). Per-origin enable lives in `prefs.sites[<host>].enabled` (default ON). On load, if `siteEnabled()` is false the script returns early but watches storage to reload when re-enabled. The overlay only mounts/connects on pages that actually have a video: `pageActive` = `SITE.hasVideo()` (YouTube: a `?v=` watch page with a laid-out `<video>`; Kick: a channel page with a `<video>`), re-evaluated by `syncPageActive()` on every `refreshDetectedHandle` (nav + 2 s poll). On YouTube `hasVideo()` also honors **`prefs.ytLoadOn`** (`"live"` default | `"all"`): in live-only mode a non-live video (`!SITE.isLive()`) reports `pageActive:false`, so the overlay never mounts/connects and no bubble shows. The popup **Site** tab's "Load chat on" select sets it (YouTube only); it applies live via the storage listener (`syncPageActive`). When inactive, `applyMode`/`applyModeVisual` tear everything down (no overlay, no bubble, IRC disconnected) and `ensureConnected()` early-returns — so the home/search feed shows nothing. Adapters also expose `findChatColumn()` for docked mode. The popup **General** tab has the master **Extension enabled** toggle (`prefs.extensionEnabled`; off reloads + unmounts everywhere) and the per-site display-mode select (Auto/Overlay/Docked — Hidden is reached via the bubble/×, not the dropdown); the **Site** tab shows the host + supported status, bind-to-player, and mappings.

## Channel resolution
1. `prefs.overrideChannel` if set (cleared via ⟲ in the channel input, **and auto-cleared in `refreshDetectedHandle` whenever the detected handle changes** — a manual override is scoped to the page it was typed on, so navigating to a different stream falls back to that channel's mapping instead of carrying the old override).
2. `prefs.mappings[<detectedYoutubeHandle>]` — handle scraped from the watch-page owner link (`/@handle`); refreshed on `yt-navigate-finish` + 2 s polling.

(No global fallback — if neither resolves, the overlay sits idle until the user types a channel.)

## Overlay layout
The root has `display: flex; flex-direction: column` and contains the (collapsible) header, the messages box (height set inline; `flex:none; min-height:0`), the (collapsible) input wrap, and absolute-positioned resize grips (one per corner) + status. Header and input animate `height: 0 → var(--meridian-header-h | --meridian-input-h)` on `:hover`/`:focus-within`. To prevent the messages text from shifting when bars expand, the root applies `transform: translateY(calc(-1 * var(--meridian-header-h)))` on the same trigger — header grows upward, input grows downward, messages stays anchored. `.meridian-dragging` disables that transition during drag/resize. Drag/resize math uses `style.top`/`style.left`/`offset*` (layout coords) so the transform doesn't pollute it.

## Idle timer
`startIdleTimer()` fires `.meridian-idle` after 10 s. **Esc in the chat input** is caught in a window-level capture listener (beats YouTube's own keydown handlers): it closes the suggest list if open, else blurs the input + collapses the bars. The browser's native Fullscreen-API Esc-exit can't be cancelled, so when fullscreen it arms a ~700 ms re-enter (`reFsEl`/`reFsUntil`, applied in the `fullscreenchange` handler) — the first Esc dismisses the input while staying fullscreen, a second Esc (input now blurred) exits normally. Activity = mouse / keys / wheel / input inside root, OR focus held on an input. `mouseleave` does NOT clear the timer if focus is still within (so an abandoned, focused input still blurs at 10 s). Typed `.value` is preserved across the forced blur.

## Drag / resize
Drag: header (always) and messages background (`e.target === els.messages` — clicking a `.meridian-msg` selects text). Resize: 4 corners (SE/SW/NE/NW). Both clamp against viewport; rect is clamped again on load.

## Autoscroll
`prefs.autoscroll` (default on). Wheel on messages pauses autoscroll for 8 s; an interval re-engages and snaps to bottom. A `scroll` listener also re-engages **immediately** if the user manually scrolls back to the bottom (within 4 px), without waiting out the 8 s. `.scrolling` class flashes on wheel to make the scrollbar thumb visible briefly. Snapping goes through `pinToBottom()` — a synchronous `scrollTop = scrollHeight` **plus** a coalesced rAF re-snap, because `.meridian-msg` uses `content-visibility:auto` (with a one-line `contain-intrinsic-size`): a freshly appended multiline row is unrendered (measured as one line) at the first snap, so without the re-snap its second line gets clipped below the fold.

## Chat delay & batch
`prefs.chatDelaySec` (0..600): client-side queue keyed by `m.ts`; pump fires when age ≥ delay. Self messages bypass. `prefs.updateFrequencyMs` (0..2000): post-delay buffer, flushed in one batch every N ms (0 = instant).

**Status banners (`.meridian-banner`).** Two share one pill style (pulsing dot + sliding shimmer, color via `--banner-color`), both floating at the top of the messages area (absolute, no layout consumed → work in overlay AND docked mode since they live inside `root`):
- **Connection banner** (`.meridian-conn-banner`, blue; `.error` → red). Driven by `connState` (set in the IRC `onStatus` callback): shows "Connecting to Twitch chat…" while `connecting`, red "…reconnecting…" on `disconnected`/`error`, hides on `connected`/`joined`. `updateConnBanner()`.
- **Delay buffering banner** (`.meridian-delay-banner`, violet). A one-shot *buffering* indicator: shows only while the delay holds back the **first** message(s) after (re)connect / channel switch / delay change, with a live countdown ("Buffering — first delayed message in Ns"), and hides for good once a delayed message has appeared (`delayPrimed`, set in `flushQueue`; re-armed in `syncChannel`/`disconnectIRC`/`setDelay`). Suppressed while the connection banner is up. `updateDelayBanner()` + a 250 ms `delayTicker` that runs only while visible.

## Display name & self-pill
`twitch-irc.js` captures the user's `display-name` (and `color`) from the `GLOBALUSERSTATE`/`USERSTATE` IRC tags — authoritative and case-correct. The cookie path also pre-fills `displayName` from Helix `/users` so the placeholder ("Send as X…") is correct before the first PRIVMSG. Own messages render `.meridian-msg.self` (name shown as a white pill; the `textStyle:"shadow"` text-shadow is suppressed on it since the pill already has a background). Other users' name colors pass through `readableColor()` (content.js), which raises the HSL **lightness floor to 0.5** — hue/saturation preserved, so vivid colors stay vivid and only near-black names get lifted (black → grey) for legibility on the dark background.

## Live viewer count
`prefs.showViewers` (default off, **OAuth only**) shows the channel's live Twitch viewer count in a **"Ghost" pill** (near-invisible dark bg `rgba(8,8,11,.52)`, faint hairline border, blurred, muted-white outline-eye icon + mono count — the "Ghost" design reference) anchored **top-right** inside the panel (`.meridian-viewers`; works in overlay + docked, drops below a status banner when one is up). `startViewerPoll()` fetches immediately then every 90 s while `viewersEnabled()` (`showViewers` && `currentAuth.kind==="oauth"`); restarted on channel switch / toggle, stopped on disconnect. The fetch is a `STREAM_INFO` message to `background.js` → Helix **Get Streams** (`/helix/streams?user_login=<channel>`) using the stored OAuth token + Client-Id (done in the background to use the extension's `api.twitch.tv` host permission). Count formatted with 1 decimal once past 1000 (`24.8K`/`1.5M`); the pill is hidden when the channel is offline, anonymous, or the setting is off (no fetch when disabled). Popup toggle on the **Chat** tab.

## Channel input
Header field prefixed with `twitch.tv/`. The ⟲ reset lives inside the input wrapper and appears when the value differs from the auto-resolved channel; clicking it clears `prefs.overrideChannel`. Auto-refills from mapping on YouTube nav. The `.meridian-channel` input **fills** its field (`.meridian-channel-scroll` is a flex container, input is `flex:1 1 auto`) so the whole field is one editable hit area — clicking the space beside the name edits it; on overflow the input scrolls internally while the prefix stays pinned. The `twitch.tv/` prefix (and the heart strip) are **not** part of the input — they keep the header's `grab` cursor and act as a drag handle (the prefix is uneditable).

**Follow heart.** When signed in (OAuth), a heart replaces the ⟲ spot in the channel field (in every mode, via `updateChannelControls()`). Twitch removed programmatic follow/unfollow in 2021, so the heart simply opens `twitch.tv/<channel>` in a new tab where the user follows/unfollows. Hidden when anonymous; the ⟲ reset still works when signed out.

## 3rd-party emotes (`src/emotes.js`)
`EmoteRegistry.loadForChannel(login, userId?)` fetches global + channel emote sets from 7TV (`7tv.io/v3`), BetterTTV (`api.betterttv.net/3/cached`), and FrankerFaceZ (`api.frankerfacez.com/v1`). Channel sets need the channel's numeric Twitch id; `userId` is passed straight from the IRC `ROOMSTATE` `room-id` tag (see `twitch-irc.js`) so channel emotes load even in anonymous mode (no Helix). When no `userId` is given, `_resolveUserId` tries a keyless FFZ room-by-name lookup first (`/v1/room/<login>` → `room.twitch_id`), then falls back to Helix `/users` (cookie mode only). `loadForChannel` is called twice per join — once from `syncChannel` (globals + best-effort channel) and again from the `roomstate` message in `enqueue`; the second call retries channel emotes only if the first came up empty (`!this.channel || size === 0`). Results are cached 24 h only when non-empty AND the 7TV fetch succeeded (or returned a clean 404 = channel has no 7TV set) — a transient 7TV failure leaves it uncached so the next session refetches rather than serving a partial set for 24 h. Cache key prefix is `v3` (bumped to flush older partial caches). `currentMap()` merges global + channel (channel overriding on name collisions) and memoizes the result, rebuilding only when a set changes. Render-time: native Twitch emotes (from IRC tags) are inserted by char-offset first, then remaining text is whitespace-tokenized and matching tokens become `<img class="meridian-emote">` wrapped in `.meridian-emote-wrap` (carrying `data-label` = name + provider). Hover shows the label via a **single shared `.meridian-emote-tip` element parented to `root`** (positioned by JS, delegated `mouseover`/`mouseout` on the messages box, flips below when short on room, hidden on scroll) — a per-emote CSS `::after` got clipped by the messages-box overflow on the top line / near the edges, so the label often didn't show. A hidden `.meridian-emote-name` text node inside each wrap preserves the emote name when the user copies the message.

## Chat input (contenteditable)
The chat input is a `contenteditable` div (not an `<input>`) so it can hold inline emote images. `inputText()` serializes its child nodes to plain text (text nodes verbatim; `img.meridian-input-emote` → its `data-name`); `clearInput()` empties it; placeholder is a CSS `:empty::before` on `data-placeholder`. It's kept single-line: `Enter` is preventDefaulted (sends), and `paste` is intercepted to insert newline-stripped plain text. Caret work uses the Selection/Range API via `caretTextNode()` / `setCaret()`. Disabled (anonymous) state toggles `contentEditable` + a `.disabled` class.

## Emote & @-mention autocomplete + inline replace
Typing triggers `maybeReplaceEmoteBeforeCaret()` then `updateSuggest()`. **Inline replace:** when a space is typed right after a complete emote token, the typed text is swapped for an inline `img.meridian-input-emote` chip (the space + caret are preserved). **Autocomplete:** `updateSuggest()` takes the caret's current word (`getCurrentWord()` works within the caret's text node, so emote chips are natural word boundaries). If it starts with `@`, `updateUserSuggest()` does a **prefix-only** match (on login or display name — "ro" → "Ross", not "styRo") against `chatters` (a `Map(lcLogin → displayName)` hard-capped at 50000 — oldest evicted — so a 100k-chatter channel can't grow memory unboundedly; the prefix scan early-breaks at ~40 matches), and completes as `@DisplayName `. `chatters` is seeded in `enqueue` from IRC `names` (NAMES/353 — includes lurkers) and `join` messages and upgraded to the real display name on `msg`, via `addChatter` (which never downgrades a known display name back to the login). Requires the `twitch.tv/membership` cap; Twitch suppresses NAMES/JOIN for very large channels, where it degrades to typed-only chatters. Cleared on channel switch in `syncChannel`. Otherwise it **prefix-only** matches the merged emote map; completing an emote inserts a chip directly. Tab always autocompletes the current word and never moves focus out of the input (if no list is open it opens one first, then completes the top match); Enter completes when the list is open else sends; Up/Down navigate, Esc closes, row click completes. Suggest items carry `user:true` (mention) or `em` (emote).

## Display mode (overlay / docked / hidden), per site
`siteMode()` returns the chosen *visible* mode `prefs.sites[HOST].mode` (`"auto"|"overlay"|"docked"`, default **auto** — never "hidden"); `siteHidden()` reads the transient `hidden` flag. `effectiveMode()` returns "hidden" when the flag is set, else resolves `auto` → overlay (fullscreen) / docked (else, when a dock anchor exists, else overlay). `fullscreenchange` + the 2 s poll re-run `applyMode()` when `effectiveMode()` flips. `setSiteMode("hidden")` sets the flag; `setSiteMode(overlay|docked|auto)` sets `mode` + clears the flag; both persist + call `applyMode()`, the single dispatcher: **hidden** → `undock()` + `hideOverlay()` + `disconnectIRC()` (bubble shows, always); **overlay** → floating overlay via `applyBoundMode()`; **docked** → `dock()`. The popup dropdown only offers Auto/Overlay/Docked; the chat bubble (always shown while hidden) restores to `siteMode()`.

**Docked mode = absolute overlay inside the native chat frame (no layout consumed).** `dock()` adds `.meridian-docked`, stops the player ResizeObserver, clears inline geometry, then overlays our chat *inside* `SITE.findDockAnchor()` = YouTube **`ytd-live-chat-frame#chat`** (the chat frame itself — reliably sized in normal/theater/fullscreen, whereas `#chat-container` collapses to `width:0` in theater) / Kick **`#channel-chatroom`** (both verified live via Playwright). It gives the anchor a positioning context (`position:relative` if static; theater's frame is already `position:fixed`), appends a **`.meridian-dock-tabs`** bar (`[<SITE.nativeChatLabel> | Twitch]` **source-badge tabs** — each tab has a brand-colored dot via `--tab-color` = `SITE.brandColor` (YouTube `#FF0033` / Kick `#53FC18`) / Twitch `#9146FF`; the active tab gets a brighter bg, a glowing dot, and a source-color underline; built by `buildDockTabs`), `position:absolute; top:0; height:34px`) and `root` (`position:absolute; top:34px; inset bottom/left/right:0`). Because both are absolutely positioned, docking **consumes no layout** — it can't push the site's chat send-button off-screen in fullscreen, and it survives theater's degenerate column. `applyDockTab()` toggles `dockChatTab` (`"twitch"` default): Twitch tab shows our opaque panel (covers the native chat iframe); native tab hides `root` so the site's chat shows through. CSS `.meridian-dock-anchor iframe#chatframe { margin-top:34px; height:calc(100% - 34px) }` reserves the tab bar's strip so YouTube's chat **shrinks to fit** below it (its top dropdown isn't covered and the send button isn't pushed off-screen — the YT chat iframe is `position:static`, so margin, not top, is needed; verified live). Retries if the anchor isn't in the DOM yet; `refreshDetectedHandle` re-docks if the SPA re-parents the frame (entering theater/fullscreen) or the tab bar went missing. `undock()` removes the tab bar, drops the `.meridian-dock-anchor` class + any inline position/min-height we set, and calls `applyBoundMode()`. **The user can freely hide the site's native chat while docked — ours stays independent.** We do *not* re-open native chat (an earlier MutationObserver that clicked YouTube's Show-chat control made it "re-enable itself" — removed). When YouTube hides chat it sets `display:none` on the frame (via `[collapsed]`/`[hide-chat-frame]`); CSS overrides that on `.meridian-dock-anchor` so the frame stays laid out, and `sizeDockAnchor()` keeps it sized per layout: **normal** → pin the frame's `min-height` to the player height (stays in the column); **theater + native chat hidden** → YouTube would make the video *full-bleed* (full width, no chat column), so we reserve the right strip ourselves: pad `#full-bleed-container` by `THEATER_CHAT_W` (402) + `nudgePlayerResize()` (a deferred `window` resize) makes YouTube's player recompute and shrink the **video** to the left, then we pin the frame `position:fixed` flush against the video's right edge. `clearTheaterReservation()` removes the padding on undock / leaving that state. An `observeDockLayout()` MutationObserver on `ytd-watch-flexy` (`theater`/`full-bleed-player`) + the anchor (`collapsed`/`hide-chat-frame`) re-runs the sizing instantly. **`dock()` mounts root into the anchor *before* calling `sizeDockAnchor()`** — the resize nudge can re-enter layout, so sizing-before-mount could otherwise strand root in the player with the docked class (covering the whole player). Our opaque panel covers the native chat on the Twitch tab; the [Site|Twitch] tab is how the user picks which chat to view. (All verified live via CDP on a real theater livestream: video 1185→783, chat flush beside, no overlap, stable across theater toggles.) The header **⧉** toggles overlay⇄docked; × sets the hidden flag; the bubble restores `siteMode()`. Docked CSS keeps bars always visible, grips/drag/resize disabled. Mode changes apply live via the storage listener; only the master `extensionEnabled` toggle (and legacy off) needs a reload.

## Timeline highlights (`src/highlights.js` + content.js)
Two stacked layers, both **live-streams-only** and gated on `SITE.hasTimeline` (YouTube only — Kick live has no usable DVR timeline) + `isLiveStream()` → `SITE.isLive()`. **Live detection is positive-signal only** (the `.ytp-live-badge` element exists on *every* video — `display:none` on VODs — so a presence test wrongly rendered the timeline on VODs): live ⇔ `#movie_player.ytp-live` / `.ytp-time-display.ytp-live` class, OR a *displayed* badge (`offsetWidth > 0`), OR `video.duration === Infinity`. All false on a VOD → highlights stay off there (verified live). The per-message hot path `feedHighlights(m)` reads cached `densityArmed` (refreshed by the 2 s render loop) so it touches no DOM; it drives both layers.

**Bar-scale mapping (critical, synced to the seekbar).** `video.seekable.end` freezes on YouTube live and drove the timeline out of scale, so `videoSeekable()` reads the progress bar's **own** range — `aria-valuemin`/`aria-valuemax` on `.ytp-progress-bar` (the exact scale YouTube draws with) — and only falls back to `video.seekable`. Each highlight stores its surge stream-time as `vt` (= `aria-valuemax` as it was when the surge's first emote arrived). Positioned by `frac = (highlightVt − min) / (max − min)` with fresh min/max each render → it scrolls left **and scales** in exact lockstep with the scrubber. `highlightVt = vt − highlightOffsetSec − (anchorLive? 0 : behindLive)`; the offset shifts markers into the past for reaction time, `behindLive` puts the off-anchor mode at the viewer's playback position. During ads the player puts the *ad's* progress on the seekbar, so `videoSeekable()` returns null while `SITE.isAd()` (YouTube `#movie_player.ad-showing`/`.ad-interrupting`) is true — the wave/markers pause rather than mis-scale. The density **wave** uses the matching wall-clock window `[now+offset−span, now+offset]` (span = `max − min`) so its crests sit under the same video moments as the markers. Click a marker → `seekTo(highlightVt)` (exact moment). `density` resets on video change so a different livestream of the same channel can't carry over.

**1. Density wave (`prefs.highlightTimeline`).** A YouTube "most-replayed"-style wave driven by chat activity (msgs/sec). `DensityTracker` (in `highlights.js`) accumulates a weight per fixed **2 s base** bucket keyed by the **seekbar stream-time** (not wall-clock — so the wave shares the emote markers' coordinate and never drifts); `series(start,end,res)` aggregates base buckets up to an adaptive display resolution. The hot path can't read the DOM, so the 2 s loop caches the live edge (`liveEdgeVt`/`liveEdgeAt`) and `feedHighlights` extrapolates `liveEdgeVt + (now − liveEdgeAt)`. Each render builds the series over `streamWindow(s)` = `[s.start+off, s.end+off]` and plots each bucket at `(t − off − s.start)/span` (off = `highlightOffsetSec`) — exactly the same mapping the emote markers use. Resolution = `resolutionFor(span) ≈ span/240` s (whole multiple of the base; finer steps + higher res, esp. for long streams), recomputed every **30 s**; `densityPeak` renormalized every **20 s**; `pruneBefore()` drops buckets older than `max(span, 600 s)`. Rendered as a quadratic-smoothed SVG area `path` with a **non-linear** vertical gradient in the user's `highlightColor` (light purple by default; topline stroke + gradient stops set inline from that color) in `.meridian-wave-layer` (32 px tall) on `SITE.findSeekbar()`, rebuilt every 2 s. `SITE.canSeek`/`SITE.waveSpanSec` are per-site hooks (YouTube: `canSeek:true`, `waveSpanSec:null` → window = the seekbar's DVR span). The 2 s loop bails when `ensureWaveLayer()` finds no seekbar. (Kick has `hasTimeline:false` — its live player exposes no DVR seekbar, only an intermittent hover-only control bar, so the wave is unsupported there.)

**2. Emote highlights (`prefs.highlightEnabled`, independent of the wave).** Can run with the wave off — `waveActive()` is true when `highlightTimeline` **or** `highlightEnabled` is on, so the wave layer still mounts to host the markers; `renderWave()` early-returns (clearing the path + nulling `lastSeries`) when `highlightTimeline` is off, and `feedHighlights` skips `density.add` then (the emote engine still ingests). The popup decouples the two toggles (`syncHighlightGating` gates retain-density on the wave, retain-emotes on the markers, anchor-live on either). `feedHighlights` extracts unique emote names per message (native IRC + 3rd-party tokens) → `hlEngine.ingest(name,url,user,ts)`. `HighlightEngine` keeps one ~12 s tumbling-window bucket per emote with a `Set` of logins, so **one viewer = one count** — O(1) per occurrence, no per-message storage. At `>= threshold` unique viewers it fires `onHighlight` (`MIN_EMOTE_THRESHOLD = 3` floor, default 5; both the threshold and the window resolve per-channel-else-global live via `getThreshold`/`getWindowMs`; relative/percentage threshold removed); further unique users fire `onUpdate`. `addHighlight` stores `wallTs` (the surge's first-emote time) + `behindLive`; `renderEmotes()` positions each via `highlightFrac()` and perches a small emote (15 px) just above the wave surface (`waveHeightAtFrac`). **Grouping is decoupled from positioning** (perf): `renderEmotes()` is a thin orchestrator — `regroupEmotes()` rebuilds the clusters and **reconciles** the marker DOM (reusing each marker's stem/dot/emote/`<img>` keyed by leader, so the `<img>`s aren't recreated), while `positionEmotes()` only slides the existing DOM along the scrolling seekbar each 2 s tick. Regrouping runs **only when membership can change**: a new/updated surge (`markEmotesDirty`, rAF-coalesced via `scheduleEmoteRender`), a seekbar-width change (fullscreen/theater/window resize → `FP` changes), the wave layer being re-homed, or a 30 s safety timer (slow span-growth merges). The clustering math itself is unchanged. Near-together emotes are **clustered** by a **greedy-by-strength** pass (`regroupEmotes`): surges are walked **strongest-first** (most unique viewers, ties → earlier/left-most) and each either starts a new marker or — if it falls within one footprint `FP` (= max rendered emote width 40px + 4px gap, as a bar-fraction — sized to the `.meridian-wave-emote img` max-width so even wide/animated emotes keep a clear gap, not the 16px square bubble) of an already-placed marker — is absorbed into the nearest such marker as a secondary. Because a surge only ever claims its own `FP`, **markers are pairwise ≥ `FP` apart (no horizontal overlap) while each still sits on the peak surge of its neighborhood**. This avoids both prior failure modes: anchoring at the group's leftmost item (marker drifted off the real peak) and single-linkage chaining (a ramp of ever-stronger surges snowballing into one giant cluster — a new marker still claims only its own `FP`, so a dense region gets one marker per `FP`, not one marker total). A top-right `+N` badge counts the *other distinct* emote names absorbed there (repeat surges of the leader's own emote collapse into the leader). Click → `seekTo(highlightVt(leader))`. Emote highlights persist per video/channel in `meridian.highlights.<host>.<id>` (debounced); both the in-memory `highlights` Map and the stored array are capped at `HIGHLIGHT_CAP` (300, oldest evicted) so a long stream can't leak memory. `vt` is the seekbar's stream-time (aria-valuemax at the surge ≈ seconds from stream start), so it maps back correctly on reload; the density wave is persisted in parallel (see `meridian.density.*` above) so both replay on the VOD. The hover **surge tooltip** is mounted on the player above YouTube's scrub-preview: leader emote + name + stream-time, a stacked-card pill of the top-3 *secondary* emotes in the group (`+N` beyond 3), then **msg/min** (= peak `densityPeak`×60) + N spamming. The popup **Clear highlight cache** button removes all `meridian.highlights.*` + `meridian.density.*` keys (live overlay drops in-memory markers via the storage listener). Adapters expose `getVideo()`, `findSeekbar()`, `videoId()`, `hasTimeline`. **Fullscreen:** while the wave is up the player gets `.meridian-has-wave`; CSS lifts YouTube's fullscreen channel-logo (`.ytp-overlay-bottom-left`) + like/dislike quick-actions (`.ytp-overlay-bottom-right`) by `translateY(-48px)` so they clear the wave + perched emotes.

## Hotkeys
Two **combos** (modifiers required): `prefs.hotkeyToggle` → toggle visibility (same as the × / chat bubble: hide ⇄ return to `siteMode()`), `prefs.hotkeyFocus` → reveal chat + focus the input. Captured in the popup (`comboFromEvent`); applied via a document-level keydown listener (capture phase).

One **hold-to-pause** hotkey: `prefs.hotkeyPauseScroll` → HOLD to pause autoscroll, release to resume + snap to bottom. Unlike the two combos this accepts a **single bare key** (e.g. `S`, `Space`) or a **lone modifier** (e.g. hold `Alt`) — its own matcher `hotkeySpecFromEvent` (mirrored in popup.js, must stay in sync). keydown sets `scrollHoldKey` (→ `shouldAutoscroll()` returns false); keyup resumes via `resumeAutoscroll()`. A bare *printable* key is ignored while an editable field is focused (so it doesn't hijack typing). The keyup→resume is deferred ~60 ms so X11 key-autorepeat (keyup+keydown pairs) doesn't break the hold; `window blur` / `visibilitychange` also end the hold so it never sticks. Popup captures it with `bindHoldHotkey` (non-modifier finalizes on keydown, a lone modifier finalizes on keyup).

## Popup
Six tabs (last selected persisted in `meridian.ui.tab`). Setting descriptions are `title` tooltips (no inline hint text):
- **General** — master **Extension enabled** toggle, per-site display-mode select (Auto/Overlay/Docked — no Hidden/Off; hiding is the bubble's job), and the **Twitch account** card (status + Connect/Disconnect; shows the OAuth redirect URL when no Client ID is set)
- **Site** — active host + supported status, "Load chat on" (YouTube), bind-to-player, and **both** channel-mappings editors (YouTube + Kick) — always shown on every site (not gated to the current host), so mappings can be edited from anywhere. Defaults come from `src/mappings.js`.
- **Chat** — delay, third-party emotes, render batching, max messages, highlight timeline (wave toggle + emote-highlights toggle — **independent**, either can be on alone + **timeline color picker** + **emote highlight threshold** (per-channel: label + hint reflect the live channel from `prefs._activeChannel`; "Save" writes `highlightThresholds[<channel>]` when a channel is active, "Set global" always writes the default `highlightThreshold`) + **emote highlight window** (`highlightWindowSec`) + **retain emote highlights / retain intensity timeline** toggles for VOD replay + clear-cache), a collapsed **Advanced** `<details>` (anchor-to-edge, timeline offset), hide-deleted, blocklist. (Autoscroll is always on — no toggle.)
- **Appearance** — background color / blur / drop shadow / outline toggles, **text style** (none/shadow/outline) + bold-text toggle (no description), opacity slider, blur radius, font size
- **Hotkeys** — toggle-visibility + focus-input combos, and a **hold-to-pause-autoscroll** key (single bare key / lone modifier allowed)
- **Reset** — per-data-type clear actions, each its own card: Disconnect Twitch (`AUTH_DISCONNECT`), Reset channel mappings (restores `DEFAULT_MAPPINGS`/`DEFAULT_KICK_MAPPINGS`), Clear per-channel highlight overrides (`highlightThresholds`/`highlightWindows` → `{}`), Clear stored emote markers (`meridian.highlights.*`), Clear stored highlight timeline (`meridian.density.*`), and **Reset extension** (two-click-armed `chrome.storage.local.clear()` + reloads the active tab). Removal helpers: `removeByPrefix(...)` + transient `resetMsg()`.

## Debugging with the extension loaded
Chrome 137+ neuters `--load-extension`, so use **Brave**: `bash debug/launch.sh [url]` launches Brave with the unpacked extension + `--remote-debugging-port=9344` on a throwaway profile (`.debug-profile`). Drive it over CDP with no deps (Node 22 global `WebSocket`/`fetch`): `CDP_PORT=9344 node debug/eval.mjs '<expr>'` evaluates in the YouTube tab; `CDP_TARGET=sw` targets the extension service worker. Set prefs by opening the popup page as a target and calling `chrome.storage.local.set` there. **Don't** use `chrome.runtime.reload()` to pick up code changes (it kills the unpacked ext) — relaunch the browser instead.
